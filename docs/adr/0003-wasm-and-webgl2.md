# ADR-0003 — WebAssembly with WebGL2 first

- **Status:** accepted; Phase 1 measurements recorded
- **Date:** 2026-10-17

## Context

CUE runs inside a portfolio page. It must load on demand, not block the rest
of the site, and work on current desktop and mobile browsers.

## Decision

- Target `wasm32-unknown-unknown`, with JavaScript bindings generated by
  `wasm-bindgen` (CLI version locked to the crate version in `Cargo.lock`).
- Render through **WebGL2** first. WebGPU is a separate, experimental build,
  never a silent fallback inside the same artefact.
- A dedicated `web-release` Cargo profile (size-optimised, `panic = "abort"`)
  with `wasm-opt` applied only once it shows a measured benefit.
- Bevy features trimmed to what the game uses, decided by measurement rather
  than guessed in advance.

## Consequences

- One artefact with broad compatibility. Safari and iOS remain the hardest
  targets and are tested early.
- The download budget is set **after** the first real build is measured
  (spec §21.3); no size is promised before then.

## Evidence (Phase 1)

Full numbers are in [`docs/benchmarks/phase-1-web.md`](../benchmarks/phase-1-web.md).

- The bundle works on WebGL 2 in Chromium: 120 FPS on the reference desktop,
  a first frame 0.4–0.9 s after clicking Play (local).
- Engine download: **≈ 4.1 MiB Brotli** (28.9 MiB raw) after stripping
  symbols, fat LTO and trimming Bevy features. The first build was 7.4 MiB
  Brotli and 91.6 MiB raw.
- `wasm-opt` shrinks the raw binary but makes the compressed download about
  7 % larger, so it is **not** part of the pipeline. This reverses the spec's
  default assumption.

Still open: real mobile devices, Firefox, Safari, and network-throttled load
times.
